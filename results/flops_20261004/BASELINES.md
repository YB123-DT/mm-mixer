# MM-Mixer 与历史基线的下游矩阵计算量

2026-10-04，在模型原属服务器 biggpu 的 CPU 上统计；无训练、无 GPU 使用。
下表是实际实现的显式矩阵乘法/卷积计算量，不是全部浮点指令或运行速度。

| 模型 | IEMOCAP MFLOPs/有效话语 | MELD MFLOPs/有效话语 |
|---|---:|---:|
| DialogueRNN | 42.78 | 53.97 |
| MMGCN | 482.41 | 54.93 |
| MM-DFN | 351.20 | 131.49 |
| M3Net | 11.71 | 29.01 |
| Ada2I | 124.89 | 87.94 |
| SDT | 289.80 | 385.88 |
| CSS | 200.96 | 286.10 |
| MM-Mixer | 69.00 | 68.72 |

## 统一的计数定义与不同的输入范围

- 一次乘加计 2 FLOPs。包含显式 dense/sparse 矩阵乘、卷积、注意力投影及矩阵乘。
  排除预训练特征提取、反向传播、偏置、逐元素运算、激活、softmax、归一化和数据搬运。
- 七个基线沿用历史计时的 32 个对话一批，顺序处理完整测试集：IEMOCAP 1623、MELD 2610
  个有效话语。总量含实际执行的 padding 计算，再除以有效话语数。
  这些数值依赖对话长度、分批和各自输入特征，不能称为完全匹配输入条件的模型比较。
- MM-Mixer 输入为固定长度的预提取话语向量；其 batch=1/32 计数已验证逐话语值一致。
  复用本目录两份 Full checkpoint 统计，不冒充新跑了完整测试集。
- 保留默认 eval forward 中实际执行的辅助分类头和诊断计算，未为某个模型单独裁剪部署路径。
  所有计数仅针对这里的保存版本/配置，不能推广为论文方法的全部可能实现。

## 必须随表保留的说明

1. **DialogueRNN 输入不同。** 历史 IEMOCAP 版本仅用文本，MELD 用文本和音频。
   不应写成八个模型全部使用相同三模态特征。
2. **CSS 为原配置架构重建。** 两个旧 checkpoint 文件缺失，按原训练日志及原代码重建，
   参数量与日志精确一致。源码审计确认该配置没有依赖权重数值的跳算路径，因此可以计数；
   不声称验证了旧训练权重下的预测。其他六个基线使用保存模型。
3. **M3Net 消息聚合另计。** HypergraphConv/highConv 通过逐元素乘法与 scatter 实现的
   消息聚合按上述主口径排除。其稀疏 MAC 等价补计分别约 0.676M / 0.164M，原始 JSON
   单列保存。即使加上这项补计，也不等于计入所有逐元素与归一化运算的完整 FLOPs。
4. **图构建成本依赖实现。** MMGCN 的 dense `D.mm(adj).mm(D)` 等运算按实际尺寸计算，
   包括跨对话的零区域；没有假设使用对角或稀疏优化替换。其两个数据集差异不能只归因于
   网络层数或参数量。
5. **参数与旧稿不一致的地方保留证据。** 本次实际实例参数也写入 CSV。
   SDT MELD 严格加载历史 checkpoint 后为 78,386,204，而旧稿为 68.95M；
   MM-Mixer MELD 正式实例为 5,712,070，而构造时为 6,106,825。
   本次没有修改旧稿表格、Main.tex 或 PDF。

在这个明确限定的口径下，MM-Mixer 的矩阵计算量在两个数据集上都低于 MM-DFN、Ada2I、
SDT 和 CSS，但并非最低。矩阵 FLOPs 的排序不能代替此前记录的运行时间排序。

## 验证与复现

14 个基线结果均完成全部测试批，每批计数前向与对应模型普通 CPU 前向的分类输出比较通过；
最大绝对差为 3.8147e-6（Ada2I），其余为 0。CSS 比较的是重建模型两种执行方式。
没有宣称完成 CPU/GPU 数值等价测试。各适配器、模型/数据/可用权重哈希、每批输入形状、
有效话语数和算子原始计数均保留。
